# KROK Analytics Pipeline

Система аналитики логов корпоративных AI-агентов для кейса КРОК.

Pipeline обрабатывает JSON-логи диалогов, определяет сценарии использования, считает токены и стоимость нагрузки, оценивает экономию FTE и формирует руководительский dashboard с ответом на вопрос: **окупается ли внедрение AI?**

## Логика работы

### Входные данные

В папке `data/dialogs/` лежат файлы вида `session_*.json`:

```json
{
  "user_id": "usr_abc123",
  "session_id": "sess_20260725_000032",
  "agent_id": "agent_sales_02",
  "department": "Продажи",
  "created_at": "2026-07-25T11:24:38Z",
  "scenario_type": "Управление коммуникациями",
  "scenario": "Сводка по почте",
  "messages": [
    {"role": "user", "content": "Посмотри почту за сегодня"},
    {"role": "assistant", "content": "Проверяю письма"},
    {"role": "tool", "tool_name": "gmail.search", "arguments": {}, "result": {"status": "ok"}}
  ]
}
```

### Этап 1: Нормализация логов и телеметрия

**Файл:** `main.py`

Для каждого диалога pipeline извлекает:

- пользователя, агента, подразделение и дату;
- первое сообщение пользователя;
- использованные инструменты и количество вызовов;
- токены пользователя, агента и инструментов;
- признаки провала и восстановленной ошибки;
- категорию и use case.

Если в источнике уже есть `scenario_type` и `scenario`, они сохраняются как `source_label`. Для неразмеченных логов применяется детерминированный keyword fallback и его источник указывается как `heuristic`.

**Выход:** одна аналитическая запись на диалог.

---

### Этап 2: Сценарии использования (Use Cases)

**Файл:** `main.py`

Диалоги группируются по категории и сценарию. Для каждого use case рассчитываются:

- количество диалогов;
- объём токенов;
- использованные инструменты;
- количество провалов и исправленных ошибок;
- репрезентативный пример запроса.

Примеры сценариев:

- «Деловое письмо клиенту»;
- «Исследование клиента»;
- «Выгрузка CRM в Excel»;
- «Контроль писем без ответа»;
- «Разбор инцидента».

---

### Этап 3: Экономика AI-платформы

**Файл:** `economics.py`

Система считает полную стоимость владения платформой (TCO):

```text
TCO за месяц = амортизация сервера
              + электроэнергия
              + команда продукта и инференса
              + лицензии активных пользователей

стоимость токена = TCO за месяц / токены за месяц
```

Экономия времени оценивается через FTE:

```text
стоимость минуты FTE = 400 000 ₽ / (22 рабочих дня × 8 часов × 60 минут)

эффект B = минуты, сэкономленные сценариями
           × стоимость минуты FTE
           × коэффициент реализации

ROI = (B − A) / A
```

Все финансовые параметры лежат в `config/economics.json`: CAPEX, срок амортизации, мощность, тариф, стоимость лицензии, стоимость команды и коэффициент реализации эффекта.

Если передать `monthly_token_capacity`, pipeline отдельно покажет загрузку сервера и корректно отделит полный TCO платформы от стоимости обработанной нагрузки.

### Этап 4: Executive Dashboard

**Файл:** `dashboard_generator.py`

HTML-отчёт `outputs/report.html` содержит:

- управленческий вердикт `B > A` или `B ≤ A`;
- TCO и стоимость миллиона токенов;
- breakeven: сколько минут и диалогов необходимо для окупаемости;
- структуру затрат: амортизация, электроэнергия, команда, лицензии;
- категории, сценарии и топ-инструменты;
- сравнение ROI между агентами;
- качество доказательств и следующие действия.

## Выходные файлы

| Файл | Описание |
|---|---|
| `outputs/report.html` | Руководительский dashboard |
| `outputs/analytics.csv` | Одна строка на диалог: токены, инструменты, сценарий, A и B |
| `outputs/use_cases.csv` | Сценарии, категории, примеры и признаки проблем |
| `outputs/agents_roi.csv` | Экономика и ROI по каждому агенту |
| `outputs/economics.json` | Детализация TCO, unit economics и breakeven |
| `outputs/data_quality.json` | Валидность файлов и источник классификации |

## Установка и запуск

Нужен Python 3.10+. Основной pipeline не требует GPU и внешних зависимостей.

```bash
# Запуск pipeline
python main.py

# Запуск тестов
python -m unittest discover -s tests -v
```

Для собственного набора логов:

```bash
python main.py \
  --dialogs-dir /path/to/dialogs \
  --outputs-dir /path/to/outputs \
  --economics-config config/economics.json
```

Pipeline автоматически:

1. читает все `session_*.json`;
2. нормализует логи и извлекает инструменты;
3. строит категории и use cases;
4. считает токены, TCO, FTE-эффект, ROI и breakeven;
5. сохраняет CSV, JSON и HTML dashboard в `outputs/`.


## Требования к данным для production

Для инвестиционного решения замените демо-допущения на фактические данные:

- usage counters модели: `input_tokens`, `output_tokens`, `cached_tokens`;
- паспортная и фактическая производительность GPU (`monthly_token_capacity`);
- реальная мощность и тариф электроэнергии;
- расходы команды платформы;
- измеренная экономия времени на выборке «до / после».

Так результат `B > A` будет не предположением, а воспроизводимым бизнес-кейсом.
